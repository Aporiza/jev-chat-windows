# JevChat-Windows 接续说明

程序使用 Windows Graphics Capture 捕获微信窗口，使用本地 RapidOCR 识别消息，再按配置调用 Jev 和起草模型。用户可以复制建议或将建议填入微信输入框，发送由用户操作。

## 约束

- 只采集自己设备上有权查看的窗口。截图、调试图像、识别到的聊天文字及候选都只在内存中处理。
- 只有模型所需的最近聊天文字与用户偏好发给已配置的服务。不会上传截图。启动更新检查只读取 GitHub 版本信息。
- 填入使用输入区的点击和粘贴。发送、转账、收款与红包控件由用户操作。
- `JEV_API_KEY` 和 `LLM_API_KEY` 使用环境变量和 Windows 用户注册表。配置文件仅存设置和手工填写的偏好。
- 使用 UTF-8 读写文本文件。

## 代码入口

| 模块 | 职责 |
| --- | --- |
| `app/capture.py`、`app/worker.py` | WGC 采集、定位消息和输入区域。画面变化先推进共享版本，再发送 OCR 结果。标题或布局无法确认时发送失效事件。 |
| `app/ocr.py` | 按气泡及邻近姓名识别发言人，按相邻帧的顺序、发言人和完整文字比较消息。 |
| `main.py`、`app/overlay.py` | 防抖调度、保存内存上下文、缓存候选、管理聊天与设置版本、展示可填入状态。 |
| `app/fill.py` | 核对目标窗口标识、当前 WGC 帧和输入位置。前台或焦点变化时停止。 |
| `core/engine.py` | `analyze(messages, relationship, ...)` 统一判断、起草和排序，返回生成时间、阶段耗时、已知用量和排序状态。 |
| `core/jev_client.py`、`core/llm.py` | Jev 和起草服务适配。各服务的接口、默认模型和协议来自 `core/providers.py`。 |

消息格式为 `(who, text[, name])`，`who` 为 `her` 或 `me`，最新消息排最后。建议版本由采集会话、画面、消息、回复对象和设置共同决定。初次看到会话时只建立基线，无法确认前后衔接时重新同步。例如首次采到空聊天时，第一条消息没有可比对的旧气泡，可能只用于建立基线。当前有效且可信的建议才允许填入。

每次分析读取一份设置快照，包括模型、密钥和会话偏好。单次生成默认 30 秒，补问也从同一时限扣除。引擎放弃已过期的结果，已经进入 SDK 或网络传输的调用可能继续至客户端返回。进程内最多有四个在途模型调用，等待空位也计入时限。分阶段保留可读到的用量，`usage` 顶层字段保留 Jev 的汇总兼容性。

## Windows 手工验收

在支持的 Windows 环境，用测试会话和已配置的模型执行。建议分别检查浅色、深色、100% 缩放及实际使用的 DPI。

1. 打开微信和助手。首次进入旧会话只建立基线，静默期间不调用分析。让对方连续发数条，核对只按最新一组消息生成。
2. 发相同文本两次、含否定词的近似文本、不同数字的文本，再让群里的两人发相同文本。对照调试视图与记录检查顺序、次数和发言人。若只识别过一个群成员，最新发言人又无法识别，检查界面显示「未指定回复对象」，且可以手动选择该成员。滚动到无重叠的旧记录，确认界面提示暂不能确认顺序。恢复后验证真实新消息可重新触发。
3. 等候选出现后先自己手动回复，或切到其他聊天再切回。旧候选应可复制，填入保持禁用。让模型响应期间切聊天，同时用助手下拉框浏览旧会话。晚到结果不能开启其他会话的填入。
4. 分别在分析和填入期间暂停采集、关闭微信、切换目标群成员、保存设置、调整窗口大小或让另一窗口获得前台。验证旧建议无法粘贴。重开微信并启用采集，确认旧建议保持失效。
5. 在正常会话点填入，检查结果只追加到输入框，且需要手动发送。再测试界面最小化、拖动、遮挡、布局不明、标题无法识别或有弹窗时的拒绝路径。检查发送、红包、转账和收款按钮均未触发。
6. 分别检查排序服务不可用、候选不足、对方明确要求停止联系和对话意图不确定。核对缺失排序不显示推荐，明确的勿扰边界不生成可填入候选。
7. 给两个会话分别配置关系、风格和目标，切换与重启后检查生效范围。检查 `config.json` 只有设置和手工填写的偏好。检查调试视图开关与本地文件。
8. 运行 `python -m unittest discover -s tests -v`，再用 `build.bat` 或 `pyinstaller --noconfirm --clean jev.spec` 打包。运行完整 onedir 产物，重复正常填入、暂停和窗口重开检查。

离线套件可以在非 Windows 主机运行。实际 WGC、DPI、剪贴板、Qt 界面、各服务 SDK 和安装版本需要 Windows 验收。采集依据为可见像素和 OCR，显示标题相同的账号及无法区分的滚动/重复画面仍受限。依赖版本以现有 `requirements.txt` 为准，完全锁定需要先验证 Windows 构建环境。
