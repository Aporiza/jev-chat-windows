# 中期演示 · 小组成员测试方案

> 目的：在周三汇报前，用**小组成员功能测试**确认「能装、能开、能演示、失败时知道为什么」。
> 这不是用户研究/问卷，不收集主观评分；只记录测试步骤、实际结果和缺陷。

## 1. 范围与原则

**测什么**

- 离线回归：`pytest`、各核心模块自测、语法编译。
- UI 预览：悬浮窗、设置页、调试视图、错误/暂停态。
- 本地三段式模拟：没有 Jev key 也能用 `--mock-jev` 跑通「判断 → 起草 → 排序」的编排。
- 真实微信只读采集：窗口识别、消息区定位、会话名、发言人、暂停/恢复、调试框。
- 失败路径：没窗口、窗口最小化、key 错、断网、剪贴板被占、关闭悬浮窗。
- 演示彩排：3 分钟脚本 + 备用录屏。

**不测什么**

- 不做 SUS/UEQ/问卷，不找外部被试。
- 不用真实私密聊天做演示；用测试账号或合成数据。
- 不测试自动发送——本项目没有这个功能，也不应该有。

**硬规则**

- 测试聊天内容用假数据；截图/录屏里不出现真实姓名、手机号、地址。
- 不把 API key 写进 `config.json`、测试记录、截图或提交。
- 点「填入」只填到测试输入框，**不按回车、不点发送**。
- 测试期间关闭其他会弹窗/抢焦点的软件，避免误判。

## 2. 角色与分工

| 角色 | 做什么 | 建议人 |
|---|---|---|
| 测试负责人（driver） | 按用例操作应用/命令，控制节奏 | 1 人 |
| 记录员（observer） | 记录通过/失败、耗时、截图、复现步骤 | 1 人 |
| 缺陷处理（triager） | 复现失败项、定级、建 issue/待办 | 1 人 |
| 演示人（presenter） | 按最终脚本彩排，准备备用录屏 | 1 人 |

人少可以一人兼两职，但**演示人必须实际彩排至少两遍**。每轮结束交换角色，保证至少两人独立跑过完整流程。

## 3. 环境矩阵

至少覆盖其中两行：

| 项 | 建议值 |
|---|---|
| 系统 | Windows 11；有条件再加一台 Windows 10 1903+ |
| 缩放 | 100%；有条件再加 125% 或 150% |
| 微信 | 当前稳定版，浅色主题，一个测试账号 |
| Python | 3.10–3.12（推荐 3.11/3.12） |
| 依赖 | 按 README 建 `.venv` 并装 `requirements.txt`；记录实际版本 |
| 密钥 | `LLM_API_KEY`（DeepSeek 即可）；`JEV_API_KEY` 有则测真实三段式，没有则用 mock |
| 网络 | 正常；另测一次断网/错误 key |

> 记录实际环境到测试记录里；同一用例在不同环境结果不同，不算“通过”。

## 4. 本地单独模拟（不需要微信 / 不需要 Jev key）

在项目根目录执行：

```powershell
# 1) 离线回归，不联网、不需要 key
python -m pytest -q

# 2) 各核心模块自测
python core/providers.py
python core/llm.py
python core/jev_client.py
python core/draft.py
python core/engine.py

# 3) UI 预览：合成数据，不采集、不联网、不操作真实微信
python tools/preview_ui.py --state ready
python tools/preview_ui.py --state settings
python tools/preview_ui.py --state degraded
python tools/preview_ui.py --state debug

# 4) 三段式模拟：只 mock Jev，起草仍走真实 DeepSeek
$env:LLM_API_KEY = "sk-..."
python tools/demo.py --mock-jev

# 5) 验证没有 Jev key 时的降级行为（只起草，不报错）
python tools/demo.py
```

预期：

- `pytest` 全部通过（当前 38 个）。
- 设置页「参考上下文」显示 `10`，不是空白；Jev 密钥提示为可选。
- `--state debug` 有合成聊天背景和彩色识别框，不是纯黑。
- `--state degraded` 有候选但没有推荐位/概率，状态栏提示未配置 Jev。
- `--mock-jev` 输出 3 条候选、推荐项、判断小抄；不代表真实 Jev 质量。
- 没有 Jev key 时 `tools/demo.py` 自动降级，输出 3 条候选和“[降级]”提示，不报 `JEV_API_KEY is not set`。

## 5. 功能测试用例

> 每条用例记录：通过/失败、实际耗时、截图路径、失败时的复现步骤。失败项按第 7 节模板记录。

### A. 安装与离线

| ID | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| A1 | 全新环境安装 | 按 README 建 venv、装 `requirements.txt`、`python main.py` | 能启动；缺 key 时打开设置页，不崩 |
| A2 | 离线回归 | `python -m pytest -q` | 全绿；无网络请求 |
| A3 | 模块自测 | 依次跑 `core/*.py` | 每个输出 `ok` 或自测通过 |
| A4 | 语法编译 | `python -m compileall -q app core main.py tools probe` | 无报错 |

### B. UI 与设置页

| ID | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| B1 | 首页预览 | `python tools/preview_ui.py --state ready` | 悬浮窗正常；候选卡片、推荐标记、填入/复制按钮可见 |
| B2 | 设置页 | `--state settings` | 「参考上下文」显示数字（重点回归）；关系/风格/模型各控件不撑破宽度；「判断 · Jev」提示写明可选 |
| B3 | 调试视图 | `--state debug` | 有合成聊天背景；绿/蓝/灰/橙/红/黄框和图例一致 |
| B4 | 错误/暂停态 | `--state error`、`--state paused` | 状态文案清楚；已有候选不被误清空 |
| B5 | 窄窗口 | 拖动窗口到 <400px 宽 | 进入紧凑模式；不出现文字重叠/按钮消失 |
| B6 | 降级界面 | `python tools/preview_ui.py --state degraded` | 候选可见；无推荐位/概率/判断摘要；状态栏提示未配置 Jev |

### C. 本地三段式模拟

| ID | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| C1 | mock Jev + 真实起草 | 设 `LLM_API_KEY`，`python tools/demo.py --mock-jev` | 3 条候选；`best_index` 有推荐；判断小抄出现在输出里 |
| C2 | 无 Jev key 降级 | 只设 `LLM_API_KEY`，`python tools/demo.py` | 输出“[降级] 未配置 Jev”；仍有候选；无推荐/排序；不是 traceback |
| C3 | 候选过滤 | 在 `tools/demo.py` 的 `MESSAGES` 临时换成注入对话（测完还原） | 复读型候选被丢弃；正常候选保留 |
| C4 | 起草不足 3 条 | 用会只给 1–2 条的模型/提示（可选） | 有追问补齐或按实际条数返回；不 IndexError |
| C5 | 降级引擎 | `pytest -q` 里的 `test_engine_degrades_without_jev_key` | 不调用 `ask`；`status=degraded`；候选保留；judge/rank 标 skipped |

### D. 真实微信只读采集（测试账号）

| ID | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| D1 | 找窗口 | 打开微信测试账号，`python main.py` | 找到窗口；不误选其他微信子窗口 |
| D2 | 消息区/会话名 | 打开一个测试会话，触发一帧 | 调试视图里消息区蓝框、头部紫框位置合理；会话名能识别 |
| D3 | 左右分人 | 测试账号发 2 条、自己发 1 条 | 对方/我分类正确；头像/表情包里的字被过滤 |
| D4 | 新消息触发 | 对方再发一条 | 只有对方新消息才触发分析；自己发消息不触发 |
| D5 | 暂停/恢复 | 拨标题栏开关 | 暂停后不再读屏；恢复后不重复上报旧消息 |
| D6 | 群聊对象 | 测试群聊里选「回复对象」 | 候选按对象重跑；填入只在测试输入框，不发送 |
| D7 | 窗口最小化 | 最小化微信 | 程序能无激活还原并继续采集；或给出明确提示 |
| D8 | 关闭微信 | 直接退出微信 | 状态变为“采集停了”；不崩溃、不无限重试 |

### E. 失败路径与恢复

| ID | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| E1 | 错误 LLM key | 设置里填错 key，触发一次分析 | 状态栏/记录里有可读错误；不泄露 key |
| E2 | 断网 | 断网后触发分析 | 超时/失败提示；恢复网络后新消息可重试 |
| E3 | 剪贴板被占 | 用截图工具占住剪贴板，点填入 | 重试或提示；不崩溃 |
| E4 | 关闭悬浮窗 | 点关闭 | 程序退出；采集子进程不残留 |
| E5 | 重启后配置 | 保存设置，退出，再启动 | 关系/风格/模型/上下文仍在；key 不写进 `config.json` |

### F. 演示彩排

| ID | 场景 | 步骤 | 通过标准 |
|---|---|---|---|
| F1 | 3 分钟脚本 | 按第 8 节走一遍 | 不超时；每一步都能接上 |
| F2 | 无 Jev key 兜底 | 用 `preview_ui --state degraded`、`demo.py`（自动降级）和 `demo.py --mock-jev` 各走一遍 | 能讲清“降级只起草、不判断/不排序”和“mock 不是真实判断” |
| F3 | 备用录屏 | 提前录一段完整流程 | 现场网络/微信出问题时能直接播 |
| F4 | 隐私检查 | 检查演示聊天/截图/录屏 | 无真实姓名、手机号、地址、群名 |

定级建议：

- **P0**：启动失败、演示主流程走不通、设置页关键值不可见、真实采集完全不可用。

- **P2**：文案、间距、非关键按钮、边界情况。

## 8. 演示脚本（3 分钟）

| 时间 | 内容 | 操作 |
|---|---|---|
| 0:00–0:20 | 问题与原则 | 说明“只读、不自动发送、人来决定” |
| 0:20–0:40 | 架构 | 一张图：截图 → OCR → 判断 → 起草 → 排序 → 悬浮窗 |
| 0:40–1:20 | UI | 打开 `preview_ui --state ready`，讲候选卡片、推荐、复制/填入 |
| 1:20–2:20 | 主流程 | 有 Jev key 则真实跑；没有则 `demo.py`（自动降级，只起草）或 `demo.py --mock-jev`，明确说“降级不判断/不排序”或“Jev 是本地 mock” |
| 2:20–2:45 | 调试视图 | 展示 OCR 框、左右分人、过滤规则；讲局限 |
| 2:45–3:00 | 收尾 | 隐私边界、下一步、致谢 |

备用方案（按优先级）：

1. 真实微信 + 真实 Jev key；
2. 真实微信采集 + 无 Jev key 降级起草；
3. 真实微信采集 + `demo.py --mock-jev`（只 mock 判断/排序）；
4. 只播 `preview_ui` + 提前录好的完整流程视频；
5. 只播录屏 + 讲架构图。

## 10. 通过标准（Definition of Done）

- A2、B2、C1、D1、F1 全部通过；无 P0 缺陷。
- 设置页「参考上下文」可见；`preview_ui --state debug` 不是纯黑。
- 没有 Jev key 时，降级模式能生成候选，界面明确提示“未配置 Jev、不判断/不排序”；团队也能切换到 mock 演示，不把降级/mock 结果说成真实判断。
- 真实采集测试只用测试账号/假消息；演示材料通过隐私检查。
- 备用录屏能在断网/微信异常时独立播放。
- `docs/CHANGELOG.md` 与实际改动一致；提交记录可追溯。
